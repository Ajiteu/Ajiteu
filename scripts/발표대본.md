## 슬라이드 3 — 프로젝트 소개 (1분)

아지트는 Instagram·커뮤니티의 장점을 참고해, **일상 공유에 특화된 웹 서비스**입니다.

- 여행, 음식, 운동, 공부, 반려동물, 취미 등 **다양한 주제**를 올릴 수 있고
- **좋아요·댓글·답글**로 서로 소통합니다
- **카테고리·이번주의 발견**으로 관심사와 트렌드를 탐색할 수 있습니다

저희가 특히 신경 쓴 점은, 매번 페이지를 새로고침하지 않고 **반투명 overlay 모달**로 게시물·프로필·글쓰기를 열어, **가볍게 탐색하는 UX**를 만든 것입니다.

## 슬라이드 7 — 화면 데모 ② 메인 피드 (1분)

*(스크린샷 가리키며)*

로그인 후 보이는 **메인 화면**입니다. 김국진님이 UI를 맡으셨습니다.

| 영역 | 설명 |
|------|------|
| **상단** | 아지트 로고 + 검색창 |
| **좌측** | 프로필, 글쓰기, 프로필 설정, 내가 쓴 글, 로그아웃 |
| **중앙** | 2열 **게시글 카드** — 좋아요·댓글·조회수 표시 |
| **우측** | 취향따라보기(카테고리), **이번주의 발견** |

카드를 클릭하면 페이지 이동 없이 **상세 모달**이 열립니다. 우측 **이번주의 발견**도 같은 방식으로 연결됩니다.

---

## 슬라이드 8 — 화면 데모 ③ 상세 모달 (1분)

*(스크린샷 가리키며)*

게시물 카드 클릭 시 **반투명 overlay** 위에 상세 모달이 열립니다.

- 본문, **좋아요·댓글·조회수**
- 하단 **댓글 입력창**
- 우측 상단 **⋯ 메뉴** → 삭제 / 수정 / 게시물로 이동 / 취소

⋯ 메뉴는 인스타그램 스타일 **액션 시트**입니다. 김시내님·김환석님이 모달·댓글·통합 쪽을 맞췄습니다.

**조회수**는 실제로 상세를 **열람했을 때만** +1 되도록, 댓글 갱신용 fetch와 분리(`track_view=0`)했습니다.

## 슬라이드 11 — 아키텍처 (40초)

```
Browser (HTML/CSS/JS)
    ↕ fetch
Flask (Blueprint: auth, post, comment, reply, profile)
    ↕ ORM
SQLite (User, Post, Comment, Reply, post_liker)
```

댓글·삭제 등은 **「클릭 → API → 성공 → 재조회 → render」** 패턴으로 통일했습니다. DOM만 직접 고치지 않습니다.

---

## 슬라이드 12 — DB & 통합 (40초)

- **User 1:N Post, Comment, Reply**
- **post_liker** M:N 좋아요
- 초기 **팀원별 개별 DB** → ORM 모델 통일 → **Flask-Migrate** → 단일 SQLite 통합

통합이 이번 프로젝트의 **가장 큰 과제**였습니다.

---

## 슬라이드 13 — 트러블슈팅 (1분)

| 문제 | 해결 |
|------|------|
| DB·API 불일치 | 단일 DB + Blueprint 통합 |
| 댓글 화면·DB 불일치 | 서버 재조회 후 render |
| 이벤트 중복 실행 | modal 1개 delegation |
| 조회수 오증가 | `track_view=0` 분리 |
| 1번째 댓글 수정 안 됨 | `data-action` + closest |
| 이번주의 발견 클릭 안 됨 | `data-post-id` delegation |

## 예상 Q&A

**Q. 왜 Flask를 선택했나요?**  
A. Python 기반이고 Blueprint로 역할 분리가 쉬워 4명이 병렬 개발하기 좋았습니다.

**Q. 조회수는 어떻게 셉니까?**  
A. `/post/detail/` 호출 시 +1. 댓글 갱신 등은 `track_view=0`으로 조회수 증가 없이 HTML만 가져옵니다.

**Q. React가 아닌 이유는?**  
A. Jinja2 + fetch overlay로 SPA-like UX를 구현했고, 학습 범위·통합 난이도를 고려했습니다.

**Q. 배포는?**  
A. 현재 로컬 SQLite. 향후 PostgreSQL + Render/AWS를 계획합니다.
